## What is it?

This project is an experiment management tool built around the SolPOC optical optimization library.

It is composed of two main components:

* an Interface used to configure and generate experiment plans,
* a Scheduler responsible for automatically executing the experiments.

The interface generates structured JSON experiment files containing all required simulation and optimization parameters.

The scheduler reads these files, launches the corresponding SolPOC experiments, manages multiprocessing execution, detects duplicate experiments, and organizes the generated outputs.

The tool is designed to simplify large-scale optical optimization campaigns and improve:

* automation,
* reproducibility,
* experiment management,
* result organization.

The scheduler supports several SolPOC workflows, including:

* anti-reflective coatings,
* low-emissivity coatings,
* spectral splitting,
* selective coatings,
* Bragg mirrors,
* fitting experimental optical signals,
* material optimization studies.

## Project Structure

The scheduler uses the following directory structure:

```txt
experiences_scheduler/
├── plan_experience/   # Pending experiments generated by the interface
├── plan_executer/     # Successfully executed experiments
├── plan_failed/       # Failed experiments
├── runs/              # Generated results
└── hashes.json        # Executed experiment cache
```

### Workflow

1. The interface generates JSON experiment files inside `plan_experience/`
2. The scheduler scans all pending experiments
3. Experiments are sorted according to their priority
4. Duplicate experiments are automatically detected using hashing
5. New experiments are executed automatically
6. Successful experiments are moved to `plan_executer/`
7. Failed experiments are moved to `plan_failed/`
8. Results are stored inside `runs/`

Each JSON file represents **one experiment**.

---

## Duplicate Detection

Before execution, each experiment plan is converted into a unique hash.

If an identical experiment has already been executed:

* the experiment is skipped,
* the JSON file is moved to `plan_executer/`,
* no duplicate computation is performed.

This mechanism prevents unnecessary calculations and avoids generating duplicate results.

## How to Use

### 1. Create Experiment Plans

The interface generates individual JSON experiment files.

Each file contains:

* optical stack definitions,
* optimization parameters,
* algorithms,
* cost functions,
* execution priorities,
* scheduler settings.

Generated files are automatically saved inside:

```txt
plan_experience/
```

---

### 2. Launch the Scheduler

To start the scheduler make sure to be in the root of the repository and run:

```bash
python -m Solpoc_optimizer.experiences_scheduler.projet_final
```

The scheduler will:

1. scan the `plan_experience/` directory,
2. sort experiments by priority,
3. check for duplicate experiments,
4. launch optimization processes,
5. save generated outputs,
6. continue until all experiments have been processed.

---

### 3. Retrieve Generated Results

All generated outputs are automatically grouped inside the `runs/` directory.

Example:

```txt
runs/
└── 2026-05-29_11h19m46s/
    ├── AR_11h19m46s_3/
    ├── PVcells_11h20m01s_1/
    ├── template_low_e_11h20m15s_2/
    ├── spectral_splitting_11h20m41s_1/
    └── selective_coating_11h21m02s_2/
```

Each experiment folder may contain:

* optimization results,
* convergence plots,
* optical response plots,
* stack visualizations,
* generated text reports.

Failed experiments are automatically stored inside:

```txt
plan_failed/
```

## Scheduler

The scheduler is responsible for executing experiment campaigns automatically from multiple JSON experiment files.

### Main Features

* priority-based experiment execution,
* automatic parameter construction,
* duplicate experiment detection,
* multiprocessing support,
* automatic result generation,
* structured experiment storage,
* failed experiment management,
* automatic plan archiving.

The scheduler dynamically converts JSON fields into SolPOC-compatible objects such as:

* optimization algorithms,
* cost functions,
* material stacks,
* wavelength domains,
* optical parameters.

### Execution Workflow

1. experiment selection,
2. duplicate detection,
3. parameter preparation,
4. optimization execution,
5. result aggregation,
6. automatic plot generation,
7. automatic report generation,
8. result archiving.

Generated outputs are automatically organized into timestamped directories for easier experiment management and reproducibility.

## Interface

The interface allows users to create experiment plans through a graphical user interface.

### Workflow

1. Launch the application
2. Select an experiment template
3. Click **Add Template**
4. Modify the experiment parameters if necessary
5. Click **Add**
6. The experiment is automatically converted into a JSON file

### Output

Each experiment is saved as an individual JSON file inside:

```txt
plan_experience/
```

These files are then processed automatically by the scheduler.

The interface makes experiment creation faster, easier, and more reliable.

## Testing

The project includes a dedicated `tests/` directory containing unit and validation tests covering both the Interface and Scheduler components.

The testing suite is used to verify:

* experiment plan generation,
* parameter conversion and validation,
* scheduler execution workflow,
* duplicate experiment detection,
* result reproducibility,
* generated output consistency,
* interface functionality and user interactions.

Examples of implemented tests include:

* `hachage_test.py` – validation of the experiment hashing system and duplicate detection mechanism,
* `result_similarity_test.py` – comparison of optimization results to ensure consistency and reproducibility across executions.

Additional tests cover various Interface features, including parameter handling, template generation, and GUI interactions.

These tests help ensure the reliability, robustness, and maintainability of the entire SolPOC Optimizer project.
